API keys

Stored in this server's own .env file - saving here writes it directly, so there's no more copying the file over by hand on a remote box. Each key is optional; leave one blank to disable whatever depends on it. Restart addon-server.js (and this admin server) after saving for a changed key to actually take effect - each only reads .env once, at startup.

Deploy

Runs git pull in this server's own checkout, then - if set below - runs a restart command afterward. The restart command depends entirely on how you run these servers (pm2, systemd, plain node, ...) - set it once for your own setup; leave it blank to just pull and restart manually.

Provider health

    
Real success/empty/error counts and average load time from every live stream request, over the last 14 days - a provider stuck near 0% is chronically broken (wrong results, dead hosts, changed site structure) rather than just unlucky on one title. Both success rate and average load time also determine the order providers are queried in on a real stream request - see the Reset button below. Sorted worst first.

Catalog test

    
Fetches manifest.json and a chosen catalog directly from the running addon-server.js - the same thing Nuvio itself would see. Use this to check whether a catalog (e.g. one of the F1/F2/F3/Academy ones) actually exists on this server before assuming it's a Nuvio-side caching issue.

    

      

      

      

    

    

    

  


  

    
Server logs

    
This process's own console output, captured in memory - no SSH/pm2/journalctl needed. Reproduce an issue (e.g. autoplay loading the next episode), then check here for what the server actually did around that time. Clears itself automatically once a day so it never grows unbounded; "Clear logs" wipes it immediately.
